## 1. 结论与优先级

本轮最重要的发现不是“应再加一种训练损失”，而是：

1. **旧实验的证明标签与评分不能直接当训练 gold。**两个替代段落不支持原复合答案里的全部细节；女妖题有身份桥接歧义，芙蕾达题的“断链”忽略了题目已经给出的前提。
2. **旧报告夸大了恢复实验的含义。**没有真实多轮历史，只能观察固定上下文下的轮次敏感性。带剑女子的首轮动作还被写错了。
3. **输入污染有直接文本证据，但造成模型幻觉的因果关系尚未确认。**旧 hypothesis 带入问题以外的片段，模型部分照搬；需要同证据、同轮次的 hypothesis 对照。
4. **确定性查询处理也可能抵消模型的新信息。**本轮实际回放发现，模型提出的“郑愁、渡魂剑”等词被历史优先合并和查询截取挤出该分支的查询列表。这个局部机制已复现，端到端召回影响尚未测量。
5. **研究方向保留，扩大训练暂缓。**先固定必要答案、桥接与题设规则，分离 reader 错误和查询处理错误；再比较同数据普通 SFT 与跨状态训练。

交付：

- 对旧 56 条预测逐条校验原 prompt、system、diagnostic 和输出；
- 对 4 个问题族建立明确保留 `unknown` 的修订标注；
- 对 12 条旧检索输出回放本地 normalizer、merge 和查询生成；
- 生成 124 条自然证据控制样本、184 个对照对；
- 生成 512 条合成闭世界控制样本、1,536 个对照对；
- 21 项自动化测试通过。

**本轮新模型推理为 0，新训练为 0，真实检索为 0。未修改生产代码、模型、原始预测或原标注。**
旧报告仅加了审计警示和新报告入口，不静默覆盖历史结果。

## 3. 标注问题：有证明图不等于干预标签正确

### 3.1 带剑女子：替代证明没有覆盖复合 rubric

旧答案把以下内容写成一个 fact：

- 女子是剑化身的伥；
- 剑属于题中剑客；
- 剑名叫“渡魂剑”；
- 镇中神秘力量使器物获得灵识；
- 再加对普通友人、恋人关系的否定。

`chunk-0016` 支持主要身份揭示；`chunk-0020` 明确支持“她是我的剑”和“剑化身的伥”，但没有给出剑名和镇中力量成因。
因此，不能把第二段标为整个原复合 fact 的等价完整证明。

修订不应要求模型补写看不见的细节。题目问“身份及关系”，必要事实收窄为“剑化身的伥＋属于剑客”，剑名和成因作为可选细节：

- 模型不写可选细节，不因此判不完整；
- 模型主动写了可选细节，仍必须有当前引用支持；
- 不能在评分时把两种规则混用。

旧 clean-SFT 的 `proof_b` 只写“女子是剑客曾经的剑”和“剑客称她我的剑”。
这两句近义，且没有明确说明化身身份，不应继续作为已认证的完整成功。
本轮将它列为待重新审阅，不通过临时放宽答案要求来保住旧分数。

### 3.2 芙蕾达：两种不同的缺口不能混为一谈

第一处问题：旧 fact 2 要求“父亲因为反抗付出代价”的因果，B 段只有父亲牺牲、自由换生存等信息，不能独立支持这条完整因果。

第二处问题更影响断链实验：题目已明确给出“镇民骂叛徒、威尔认为保护大家”。
删除直接并列两种立场的段落后，剩余芙蕾达说明妥协动机的段落，可能仍足以结合题设解释分歧。

所以必须先决定：

- 题设中的事实能否作为回答推理的前提？
- 若能，答案复述题设时是否必须再配一条独立原文引用？
- 问题是要求解释分歧，还是要求重新证明两方曾表达这些立场？

当前 prompt 没有明确这些边界。本轮把两条 Freda `broken` 状态标为 `unknown`，不是强行改成充分，也不是继续作为确定不足。

### 3.3 女妖：所谓干扰段可能是身份桥接

证明 A 的主体是“那位女士”，证明 B 的主体是拂哀菈，题目问的是“虚弱的女妖”。
故事阅读中可以通过场景推断它们指向同一人，但冻结候选池没有显式的别名等式。

原来的“干扰段”恰好提供了虚弱女妖、骸骨荒原和寻人的场景。这类段落可能补的是主体消歧，而不是答案姓名。
因此，不能从加上它后模型开始回答，直接得出“模型抗干扰变好/变坏”。

本轮保守隔离这题五个原正状态：

- `unknown` 表示尚未固定身份桥接接受标准；
- 不表示“娜斯提这个答案错了”；
- 单独只剩没有姓名的“她”时，仍判不足；
- 母女关系是支持和消歧信息，不是题目额外要求的第二个答案槽位。

### 3.4 迷迭香：唯一旧全循环成功不等于独立证明推理成功

A 为 1,089 字符，B 为 1,096 字符。最长连续逐字相同部分有 **1,053 字符，占较短段 96.69%**。
这个数字由 [重叠审计](audits/evidence_overlap.json) 直接计算。

它能测试冗余片段下的稳定性，但不能代表独立、多跳的替代证明推理。
四个自然问题族也不等于四个满足 `(e1∧e2)∨(e3∧e4)` 的独立两跳样本。

## 4. 重算后可以保留什么结论

### 4.1 暂不再发布“主成功率”

旧语义审阅存在以下问题：

- clean-SFT 的带剑女子 B 被过宽地判为完整；
- base 带剑女子 A 的“失去人类形态”与原文方向相反，旧说明漏掉了这一点；
- base 芙蕾达 A 和双证明的审阅说明，写入了实际输出里没有的“芙蕾达认为威尔是叛徒”；
- 女妖的身份桥接尚未定义；
- 旧协议检查没有语义级近义重复/冗余事实检测；
- 部分所谓“引用缺失”同时受题设是否可以作为前提的规则影响。

因此，旧的 `4/28 vs 14/28` 和 `0/4 vs 1/4` 只能留作历史计算，不能继续当可靠准确率或训练提升证据。
本轮没有为了生成一个漂亮的新分数而再快速贴满 56 条语义标签。

### 4.2 仅在暂可判定的 21 个状态上统计动作

每个 reader 的 28 个状态中，本轮保留 15 个充分、6 个不足，另外 7 个隔离。
状态不是独立问题；必要事实规则也已修订，不能与旧表直接纵向比较。

| 指标 | base | clean-SFT |
| --- | ---: | ---: |
| 充分状态选择回答 | 15/15 | 12/15 |
| 不足状态按轮次检索/弃答 | 2/6 | 6/6 |
| 暂可判定状态动作一致 | 17/21 | 18/21 |
| 隔离状态 | 7/28 | 7/28 |

这些是动作计数，不含答案内容、引用正确性和查询质量，不是问答正确率。
可以保留的弱结论是：在这个开发小样本上，base 更愿意回答；clean-SFT 更容易停止，但也会在充分上下文中不回答。

### 4.3 精确的轮次对照只有三题

下面三对输入除 `round: 1/2 → 2/2` 外，system、question、hypothesis、证据正文、顺序和 E-ID 全部相同：

| 上下文 | base 首轮→末轮 | clean-SFT 首轮→末轮 |
| --- | --- | --- |
| 带剑女子 B＋场景段 | 回答→回答，输出逐字相同 | 检索→弃答 |
| 迷迭香 B＋能力段 | 回答→回答 | 回答→回答 |
| 女妖 B＋场景段 | 回答→回答 | 回答→弃答 |

芙蕾达对应两状态同时改变了段落内容与顺序，排除出 round-only 对照。

这支持“部分输出对轮次字段敏感”的观察。它不支持以下说法：

- 模型经历过失败，所以产生了心理式或记忆式的“恢复惯性”；
- 带剑女子首轮回答、末轮弃答；
- 已完成真实第二轮检索；
- 已经证明这种行为来自特定训练数据或损失。

女妖的动作变化可以在不裁定其语义标签时客观记录，但不能据此计算可靠的“错误弃答率”。

## 5. 输入污染和查询处理：比增大 reader 训练更早的诊断点

### 5.1 hypothesis 不只是问题改写

带剑女子输入含 12 个关键词，包括：

`失剑后出现、她渴望成、剑客但、无法离开、剑客曾、她取名`

其中有证据/答案片段、残句和容易诱导方向错误的短语。旧构造器把整个 snapshot hypothesis 原样复制进所有状态。
即使删掉一段证据，这些片段也没有随证据消失。

这里要区分两点：

- 初始 hypothesis 和输出 follow-up 并不一定使用同一字段限制，不能仅凭初始有 12 词就说生产输入 schema 非法；
- 但作为“仅改变证据”的研究，它不是干净的 question-only 条件，且示范了与输出“最多 8 项”要求不同的列表形态。

clean-SFT 的 A 状态写出“无法离开剑客，因为剑客是她存在的根源”，原文没有这个因果。
它与输入中的“无法离开”相呼应，但还不足以认定输入片段导致幻觉。新控制数据已经把“整份 inherited hypothesis vs question-only”单独列为因素；该对照衡量整个字段包，不单独识别某个词的作用。

### 5.2 旧严格评分不等于运行时是否接纳

对全部旧 `retrieve_more` 输出，实际调用当前本地代码：

`normalize_hypothesis_payload → normalize_conclusion_payload → merge_hypotheses → build_follow_up_hypothesis_queries`

| 指标 | base | clean-SFT |
| --- | ---: | ---: |
| 原始检索输出 | 5 | 7 |
| 通过旧严格协议评分 | 0/5 | 2/7 |
| 当前 normalizer 接纳 | 5/5 | 7/7 |
| conclusion normalizer 保持检索动作 | 5/5 | 7/7 |
| 生成非空查询列表 | 5/5 | 7/7 |

当前 normalizer 容忍 follow-up 的 `intent`，能补缺少的 answer type，去重并扩展关键词；它不是旧评分器的严格 schema。
canonical Exx prompt 本身也没有列出完整 follow-up 字段表。

所以“格式欠规范”仍成立，但“这些查询都无法执行”没有依据。
反过来，接纳和生成非空查询也不能证明能检索到缺失证据。

这是**当前本地工作树**的回放，不是对历史远端运行时实现的认证。相关源码哈希保存在回放文件中。

### 5.3 已复现：历史词挤出新证据词

base 带剑女子 `broken_round1` 的模型输出包含“郑愁、渡魂剑、天师府”等词。
它们可以在该状态可见原文中找到相关来源。

用相同代码做局部对照：

| 输入查询生成器的 hypothesis | 生成列表的有关内容 |
| --- | --- |
| 归一化后的模型 follow-up，不合并旧 hypothesis | 包含“郑愁”“渡魂剑”“天师府”“抢夺武典” |
| 按现管线先与旧 hypothesis 合并 | 上述具体词退出列表，留下“女子究竟”“她渴望成”等旧项 |

原因是两层截取：

1. `merge_hypotheses` 把旧 entities/keywords 放在新项前面，再限长；
2. 查询生成器优先使用靠前的 entities/keywords，最后最多保留 14 条查询。

本题中 base 的断链输出、clean-SFT 的断链输出、clean-SFT 的 B＋场景输出，
虽然原始跟进 JSON 不同，最终这一路生成的 14 条查询却完全相同。

还有一个人工构造的边界测试：旧 entities 满 12、keywords 满 20 时，新 follow-up 提出的唯一桥接实体和缺失关系会全部被 merge 丢掉。
这是代码反例，不是自然样本中发生频率的估计。

上述确定性结果提示：如果只优化模型查询监督，却不检查下游消费方式，可能把模型学到的新信息重新丢掉。
但系统还有其他查询分支，本轮没有实际检索，不能直接断言整个系统漏召回。

## 6. 已准备的单因素控制数据

### 6.1 自然语料：124 条，184 对

[数据](data/natural_controls.json) 和 [对照索引](data/natural_pairs.json) 使用原冻结正文，未修改剧情文本。

控制因素：

- 62 对：只改 round；
- 62 对：只改 hypothesis 整个字段包；
- 44 对：只置换 E-ID，证据内容与展示顺序不变；
- 16 对：在 B 后追加场景/干扰段，保留原 B 编号。

追加上下文仍改变长度和段数，所以明确标为 **not length matched**，不伪装成严格的单一“干扰语义”实验。
女妖新增段还标为潜在身份桥接，不能与纯无关段合并解读。

124 条包括：80 条暂定充分、12 条不足、32 条未知。所有样本均 `evaluation_only`、`exclude_from_training`；未知状态没有强制动作 target。
正常推理输入仅 system 和 human prompt，不含离线标签、答案或证明图。

### 6.2 合成闭世界：512 条，1,536 对

为避免剧情共指歧义先污染方法诊断，构造 8 个明确虚构的登记簿世界。每个世界：

- 查询某箱号的通行口令；
- 两条互相独立的两跳路径指向同一口令；
- 固定六段正文，包含正确口令候选和两个错误候选；
- 穷举四条关键关系的全部 16 个开/关状态；
- 再交叉两个 round、两个 E-ID 映射。

“关闭”一条关系的实现是把其主语替换成同长度的无关实体；它是关系替换实验，不是字面删除或实际检索补入。
保留每个位置字符数、段数、正确及错误候选字符串的出现次数，减少用篇幅或答案词是否出现的捷径。

独立图遍历核对全部状态：

\[
A(E)=(e_1\land e_2)\lor(e_3\land e_4)
\]

16 种状态中 7 种充分、9 种不足；展开为 224 条充分、288 条不足。
每个充分状态保留所有合法双引用组合，每个不足状态计算最小关系修复集合，而不是指定唯一 gold ID。

对照索引包括：

- 256 个 round-only 对；
- 256 个 E-ID-only 对；
- 1,024 个只修复一条关系的对。

限制：

- 字符数匹配不代表 tokenizer token 数匹配，尚未进行 tokenizer 测量；
- 8 个世界仍复用一个语言模板、固定文段角色位置，全部是开发诊断，不是泛化测试；
- 题目明确告诉模型两跳规则，任务比自然语言证据判断更理想化；
- 512 是控制输入数量，不是 512 条已完成的模型实验；
- 后续仍需新模板、随机段落顺序、真实删除/添加和自然证据桥接测试。

### 6.3 自动化验证

21 项测试覆盖：

- 源文件哈希及 56 条预测与输入的精确关联；
- 重复 ID、重复 JSON 键、prompt/system/输出篡改拒绝；
- round 正则只修改指定行，不改正文；
- 全部对照只修改声明字段；
- unknown 不强贴 target，离线图不进入模型消息；
- 16 状态真值表、可达性、最小修复和合法引用；
- 合成段落长度、数量和候选词出现次数匹配；
- 构造可重复；
- 真实剑客跟进词在历史合并后退出该分支查询的回归测试；
- 饱和历史列表丢弃新信息的构造反例。

测试验证程序与控制设计，不验证自然语义标签已被独立人审。

## 7. 对方法本身的进一步收窄

### 7.1 支持证明存在，与证明不存在，是不对称的

在证据可靠、没有未处理矛盾且事实范围固定的条件下，找到一个完整证明，可以认证充分。
但“已标注证明都不成立”只能排除已知证明；若标注不完备，不能据此认证不足。

建议标签包含两个独立的审计信息：

- `support_witness`：当前可见正文能支持哪些必要原子事实、主体/时间对应是什么；
- `negative_audit_scope`：当前可见集合的其他可能证明是否已检查，哪些共指或题设规则仍不确定。

这里的“当前可见集合”不是整个语料库。语料库可能有答案，但当前输入仍不足；不需要为了判当前输入不足而穷举整个语料库。
反之，已标注候选池不足也不等于模型可见全文中没有未标注的证明。

对完全已知的两条独立两跳证明，破坏所有证明的最小删除集合是：

`{e1,e3}、{e1,e4}、{e2,e3}、{e2,e4}`。

删除 e1 一个节点不会破坏 B。这一组合事实在合成任务可自动证明；真实文本中的证明集合是否完备仍须语义审核。

### 7.2 不把主体、转述与时间从证明中删掉

本轮错误大量发生在“谁认为谁是什么”，不是实体名字有没有出现。
后续原子事实宜使用离线标注结构：

`主体—关系—客体—发言/归因来源—时间/条件`

身份桥接也是证明的一条边。“拂哀菈在找娜斯提”并不自动支持“题目那个未消歧女妖在找娜斯提”。
此结构仅用于离线标注和评分，暂不要求修改现有部署 JSON。

### 7.3 避免不正确的一致性训练

不能对同题所有状态的原始动作分布一律做一致性约束：

- 充分状态改变轮次，应仍回答；
- 不足状态首轮检索、末轮弃答，这是应有的变化。

也不能把所有非引用答案 token 强制逐字相同：替代证明允许不同合法措辞，不同上下文允许不同可选细节。

建议先做最小可检验目标：

1. 普通 SFT：只使用已认证必要事实和合法引用；
2. 对充分/不足配对约束“回答”相对于“非回答”的动作分数；
3. 只在必要事实层做内容保持检查，不约束可选细节逐字一致；
4. 引用允许所有合法最小支持集合，重编号后按映射变化。

动作分数若由生成模型得到，应使用固定序列化的完整 action 字符串似然，不能假设动作名是一个 token，也不能把候选内归一化的数值称为校准置信度。

对固定事实文本的引用，可对不同合法序列化 citation set 的概率求和，避免只奖励原 gold ID。
先去重等价 citation set；不要把有交集的“证明事件概率”直接相加冒充整个可答概率。
这仍是待实现方案，未运行训练。

### 7.4 Reader 与查询处理必须分开消融

最小后续设计：

| 对照 | Reader | 查询处理 | 目的 |
| --- | --- | --- | --- |
| A | 冻结现有 reader | 当前处理 | 历史参照 |
| B | 同一个 reader、缓存相同输出 | 仅研究性改变新旧词优先级 | 测量查询处理贡献 |
| C | 同干预数据普通 SFT | 与 A 相同 | 测量数据贡献 |
| D | 同数据＋跨状态目标 | 与 A 相同 | 测量训练目标贡献 |

不要同时修改 reader 和 query merge 后把全部增益归因于“替代证明训练”。
分词/实体净化、直接缺口查询也应先作为低成本基线；若它们就解决主要问题，需要据实缩小论文主张。

## 8. 真正的恢复实验怎样做

旧“restored”只是静态上下文名。真正闭环应分别记录：

1. 断链上下文下生成动作和跟进查询；
2. 当前代码实际消费后送给检索器的 query；
3. 检索实际召回、去重、选择后进入 prompt 的证据；
4. 是否新增了合法证明所需的关系；
5. 第二轮输出的必要事实和逐事实引用。

先跑两种不同恢复：

- **oracle 补证**：人工补入已核验的缺失关系，仅测 reader 是否能利用；
- **真实检索补证**：只根据实际发出的查询找证据，测端到端修复。

部署如果不给 reader 上一轮回答，就不要为了研究“惯性”偷偷加一段失败对话。
应忠实保留实际控制器状态，再用相同最终证据的 stateless replay 做对照。

主指标分开报告：

- 充分时完整且受支持的回答；
- 不足时停止无依据回答；
- oracle 补证后的 reader 成功；
- 发出查询后的实际证明增量；
- 最终完整正确率；
- 格式合规、运行时修复率、查询覆盖和调用成本。

## 9. 文献勘误和新颖性状态

检索工具在本轮返回空结果，另用直接 HTTP 获取原始出版页并保存响应与哈希。
详见 [文献核验](audits/bibliography/verification.json)。

- 旧 `2021.emnlp-main.315` 的出版页标题是 *Virtual Data Augmentation: A Robust and General Framework for Fine-tuning Pre-trained Models*，不是旧文档声称的 false-negative-contexts 论文。该引用链明确有误，不能沿用。
- `2022.tacl-1.31` 的标题与 MuSiQue 对应；本轮只核对书目信息，没有据此宣布完整阅读或复现其方法。
- CUE-R、Pair-ID、GRAB-RAG 三个旧 arXiv 条目在直接请求时连接失败。本轮未核实；不能因无法访问就说论文不存在，也不能继续引用旧报告中的具体方法或发布日期为已证实事实。

因此撤回旧报告“尤其是某篇最新工作已经覆盖某贡献”的确定口吻。
当前不能宣称首创，也不能宣称已被特定新论文完全覆盖。完成可核验的全文近邻对照仍是立项门槛。

## 10. 下一步执行顺序与停止条件

### 第一阶段：先建立不自相矛盾的评测

1. 对四题的必要事实、题设和身份桥接规则做独立复核；保留争议而非投票强制二分类。
2. 有明确可用 GPU 后，先跑 124 条自然控制，对 hypothesis、round 和 E-ID 分开解释。
3. 再跑 512 条合成控制；固定 base、adapter、non-thinking 模板和生成预算，记录 token 长度、原始消息和逐条输出。
4. 重复关键对照以检查数值/批处理顺序稳定性；所有新结果与旧结果分目录。

### 第二阶段：验证是否真需要新训练目标

1. 先按故事/事件和重叠原文分组切分，再生成所有变体；当前 strict9 与八个合成世界均只作开发数据。
2. 扩建独立自然问题族，单列独立替代证明、近重复冗余、部分事实替代。
3. 在相同数据、相同训练 token/步数与种子条件下比较普通 SFT 和跨状态目标。
4. 对不同方法按独立问题族配对报告结果和不确定性，不能把同题几十个变体当独立样本。
5. 最后才做真实检索修复，保持 reader/控制器消融可归因。

应停止扩大或修改主张的情况：

- 清理输入/查询处理已解释大部分收益，而新训练目标无额外收益；
- 只改善拒答、不改善充分状态回答；
- 只在相邻重复段或单一合成模板上有效；
- 优势不超过同数据普通 SFT；
- 标签审阅分歧大到无法稳定复现结果。
