# ASA 创新点筛选：从替代证据走向保留归因作用域的证明替换

研究批次：`innovation_discovery_20260910`。沿用 non-thinking 管线；本目录与生产代码、既有实验分离。

## 1. 结论

**首推：面向问题目标、保留归因作用域的替代证明后训练。**

可检验的主张是：

> 对同一个问题，训练模型区分“换了一套仍然合法的证明”和“词面相似但归因、否定或时间范围已经改变的伪替代证明”，能否在保持正确作答的同时减少错误抢答，且优于相同数据、相同计算预算的普通 SFT？

这保留了原 Word 文档第一项的核心，但不再把证据简单看成无条件成立的实体关系边，也不要求所有证据变化后都维持相同输出。
**这是值得做 pilot 的研究假设，不是已经确认的新颖性或模型增益。**

本轮新增实证是 12 条旧输出的完整查询构造回放，以及 84 条底层词法校验探针。
没有新模型推理、真实检索、训练或当前系统正确率测量；没有修改生产管线。

| 优先级 | 候选方向 | 项目依据 | 要超过的强对照 | 当前判断 |
|---|---|---|---|---|
| 1 | 问题目标下、保留归因作用域的替代证明训练 | 原文归因难例；词法检查误放/误杀；旧替代证明标签范围有误 | 相同数据普通 SFT、文本 NLI、作用域结构方法、同 schema 提示 | 最适合作为主线，但近期近邻很强 |
| 2 | 面向实际执行查询的缺口修复训练 | normalizer→merge→查询分支会改变模型动作 | 新词优先等工程修复、普通 query rewriting、同查询预算 | 先测真实检索；不能由分支碰撞夸大为系统失效 |
| 3 | token 预算内的互补证明集选择 | chain 分数回写到单段，再按单段排序截取 | top-k、MMR、动态选择、同预算 bundle/beam 搜索 | 合理备选，暂未证实自然样本上的选择损失 |

原文第三项“持续记忆压缩”暂缓：它需要真正的多次压缩轨迹、未来信息隔离和新标注。
当前固定上下文实验不能冒充记忆退化或多轮恢复实验。

## 2. 本轮究竟验证了什么

### 2.1 完整查询回放纠正了一个过强推断

调用当前工作树的 `normalize_conclusion_payload`、`prepare_next_round`、`build_initial_queries`，
并单独模拟可选 scheduler。输入来自上一轮两组预测中的 12 条 `retrieve_more` 输出。

回放文件：[full_query_pipeline_replay.json](audits/full_query_pipeline_replay.json)。
源码：[query_flow.py](../../src/asa_arknight_story_agent/inference/pipeline/query_flow.py)、
[scheduler.py](../../src/asa_arknight_story_agent/inference/pipeline/scheduler.py)。

带剑女子的三条跟进输出给出了清楚的区分：

| 观察层 | 结果 |
|---|---|
| 独立 follow-up 查询分支 | 三条输出生成同一组 14 条查询 |
| 综合查询 | 三条不同；base 断链输出的“郑愁、渡魂剑”仍保留在此处 |
| 完整 pending query 列表 | 三组不同，不能宣称它们是同一个完整执行动作 |
| 重建初始查询后再过 scheduler | 各剩一条综合查询；只是模拟，不是历史实际发出记录 |

base 断链输出在完整待执行查询中未保留的新词是“抢夺武典、恶事”，不是“郑愁、渡魂剑”。
没有检索结果，不能判定这两个词的消失是否降低召回。
保留一个词也不等于检索器实际利用了它；还可能有 tokenizer、长度、混合检索等后续影响。

因此，上一轮结论只能限定为**分支级的新信息挤出**。本轮不支持“这些关键实体退出了全系统查询”。
今后讨论动作等价类，必须基于完整查询、实际 scheduler 状态和固定检索实现，而不是某一路字符串。

### 2.2 84 条探针显示词面合规与语义支持可以分离

数据：[attribution_scope_probes.json](data/attribution_scope_probes.json)；
逐项结果：[lexical_scope_probe.json](audits/lexical_scope_probe.json)。

组成：

- 72 条合成：4 组名字 × 6 种语义模板 × 3 个主张标签；
- 12 条自然开发主张：6 对正确/错误改述，来自冻结原文，部分共享同段及相同正句；
- 每条分别调用 E-ID 与 quote 的底层 validator，总计 168 次规则调用；
- 全部 `exclude_from_training=true`；合成语义由构造器指定，自然语义为 Codex 原文复核，不是独立人审 gold。

下表的“通过”仅指**没有 hard issue**：

| 输入 | 检查器 | supported 通过 | contradicted 通过 | not_established 通过 |
|---|---|---:|---:|---:|
| 合成 | E-ID | 20/24 | 8/24 | 8/24 |
| 合成 | quote | 24/24 | 24/24 | 24/24 |
| 自然开发 | E-ID | 0/6 | 无此标签样本 | 1/6 |
| 自然开发 | quote | 6/6 | 无此标签样本 | 6/6 |

例如，在本轮原文复核口径下：

- 正确的“汤姆骂芙蕾达是叛徒”被 E-ID 检查拒绝：原文是威尔转述，表层词序不同；
- “麟青砚认为剑化身的伥戾气难去”被拒，错误换成“剑客认为”却没有 hard issue；
- 合成的“没有同意申请”原文，并不保证规则会拒绝相反主张。

**不能把表格读成模型幻觉率或生产放行率。**输入主张不是新模型生成；quote 分支还会返回 warning，
外层可能改写答案或拒绝；这里没有运行完整 serving gate。
六个模板换四组姓名，也不是 72 个独立语义问题。

这些反例足以否定“引用存在＋关键词覆盖能够保证语义支持”，不足以估计其自然发生频率。
下一步应做全管线归因和独立自然评测，不能把所有 hard issue 直接删除。

### 2.3 源码中的集合选择风险仍只是候选机制

[hybrid_chain_scoring.py](../../src/asa_arknight_story_agent/retrieval/hybrid_components/hybrid_chain_scoring.py)
把链模型分数、角色和相关性组合成各成员分数，随后按单文档最终分数排序取 `top_k`。
这一实现没有保证选中的结果保留某条完整支持链。

这说明可以研究“打分好的组合，是否在后续选择时被拆散”，但不能据此认定每次都会拆散，
也不能推断改成 bundle 一定提高回答。此前取消去重的开发实验并未给出可推广收益，不能忽略这种负结果。

## 4. 首推方向的精确定义

### 4.1 从“边存在”改成“这条证明允许回答什么”

无类型关系图容易把以下内容压成同一个命题 P：

```text
SAY(甲, SAY(乙, P))       甲转述乙的话
BELIEVE(甲, P)           甲的观点
P                       不带归因的断言
NOT(SAY(甲, P))          甲没有说 P
SAY(甲, NOT(P))          甲说“不 P”
```

它们不能无条件互推。谁说、谁认为、谁做了、何时发生，以及否定在哪一层，都影响支持关系。
同时，不能机械要求两条证明的整棵图逐字相同：表达方式和与问题无关的信息可以不同。

令：

- `E`：reader **实际可见**的证据，不包括被截断内容、隐藏候选池或答案片段 hypothesis；
- `Pq`：协议明确允许使用的题设前提；
- `Rq`：问题要求的必要答案内容；可选细节分开；
- `G`：离线审阅的出处、角色、时间和作用域结构；
- `Aq(E; Pq, G)`：在这些规则下可接受的必要答案集合。

合法替换应在 `Rq` 的语义投影上保留可接受结论，而不要求措辞、所有细节、E-ID 或完整图结构一致。
如果不同必要要点依赖彼此不兼容的主体或时间绑定，也不能逐条“各有一个证据”就算整体充分。

这里的 `G` 是标注工具，不是世界真理，也不能泄漏到测试输入。
自然语料中不能穷尽证明时，应标注未知；“有限候选池里未找到”不等于整个语料无答案。

### 4.2 必须分开三层标签

| 层次 | 标签或结果 | 容易混淆的地方 |
|---|---|---|
| 固定 claim 对当前证据 | supported / contradicted / not_established；冲突单列 | not_established 不等于 contradicted |
| 当前问题是否可答 | 有合法完整答案 / 缺少必要信息 / 标注未知 | 固定 claim 被反驳，问题仍可能可答 |
| 预算下的系统动作 | 回答 / 检索 / 弃答等现有协议动作 | 检索到新文档不等于补齐支持 |

例如原文“没有同意”，问“是否同意”，可以完整回答“没有”。
不能因为正向 claim“同意了”被反驳，就训练模型弃答。

若同一作用域、同一时间下既有支持又有反驳，要单列冲突；若两个角色观点不同，则可能只是正常分歧。
“标注者无法确定”是 annotation unknown，不是模型要输出的第四个事实标签。

转述材料的使用还需要明确任务口径：问“某人声称什么”与问“事实是否发生”不是同一任务。
本研究验证的是给定来源与题设政策下的可支持结论，不宣称仅凭内部文本就能识破所有谎言或伪造来源。

### 4.3 一个最小干预族

以下是设计示例，不是新自然模型结果：

| 状态 | 构造条件 | 应观察的行为 |
|---|---|---|
| A | 一套完整支持 | 正确回答并引用当前 A |
| B | 内容有差异但对必要结论仍充分的另一套支持 | 保留必要结论，换用 B 引用，不补写 A 独有细节 |
| AB | A、B 均可用 | 接受任一合法支持，不能只认预设 gold ID |
| scope-broken | 所有合法支持均失效，留下词面接近但归因/否定范围不支持所需答案的文本 | 不继续输出原来的无支持结论 |
| static-repaired | 在断裂输入中补回必要支持 | 固定上下文下重新作答；不能称已完成真实多轮恢复 |
| renumbered / reordered | 仅变编号或顺序 | 必要语义保持，引用随映射变化 |

`scope-broken` 必须逐题确认真的没有其他合法完整答案；若正确答案应变成“否”或另一角色，应另建 answer-changed 类型。
长度、片段数、答案名字出现、否定词数量和轮次需匹配或交叉控制；不能让“看见没有就弃答”成为捷径。

两套几乎复制的原文可以测试冗余稳定性，却不证明独立多跳推理。
两个来源重复同一传言也不等于两份独立事实确认。

## 5. 最小可实施训练方案

**只动一个实验 adapter，冻结检索、生产 schema 和 non-thinking 解码。第一阶段不加在线图谱服务或端到端 RL。**

1. 用通过验收的状态训练现有 Exx 输出：动作、必要原子事实、当前引用、缺口查询。
2. 在训练阶段增加短格式的 claim 支持状态任务；图和标签仅供构造与监督，不给部署 reader。
3. 对合法替代对施加支持状态/动作的语义一致约束；对答案改变或断裂对监督正确差异，不比较完整输出字符串。
4. 对相同样本、相同辅助任务去掉第3步，得到最重要的普通 SFT 对照。

一个待实现的最小目标可以写成：

`L = L_Exx + α L_status + β L_pair`

其中 `L_status` 是训练期三标签短输出；对非冲突、已审定主张归一化标签序列概率得到 `pθ`。
`L_pair` 对合法保留关系使用分布一致约束，对已确认的状态改变使用有监督差分约束；
若只是引用编号变化，仅对语义状态约束，引用仍由当条 Exx 目标监督。
具体权重、margin、采样和 token 归一化只能在开发集选定；本轮未实现或验证该损失。

这不是“写出一个损失函数就有创新”：普通 SFT 可能已学到同样关系。
若配对项没有独立增益，应将成果收缩为数据/评测研究，不继续包装为新的后训练方法。

### 必需基线与消融

| 对照 | 隔离的因素 |
|---|---|
| 冻结 base、历史 adapter | 是否仅为特定 checkpoint 的问题 |
| 原有干净 SFT | 与当前训练路线比较 |
| 同一新数据、同一辅助任务、同 token/step 的普通 SFT | 数据改善与配对目标分离，最关键 |
| 同结构字段的提示、抽取式上下文窗口 | 是否只是更清楚的输入/更多上下文 |
| 文本 NLI 与 Source–Cue/FactGraph 类结构方案 | 是否只重复已有蕴含或归因能力 |
| 同预算随机配对、去作用域、去替代支持、去查询监督 | 配对关系、作用域、替代标注、检索监督各自贡献 |
| 金标准结构 vs 预测结构 | 防止把 oracle 标注收益当部署收益 |

语义解析的中文适配和模型调用成本也必须计入。若没有真正复现原论文代码/数据，应称“方法适配基线”，不能标成论文复现分数。

## 6. 两条备选方向怎样避免退化成工程修复

### 6.1 执行感知的缺口修复

定义实际查询动作：

`T(h, s) = scheduler_s(all_query_branches(merge(normalize(h), history)))`

优化对象应是 `T` 发出的查询能否新增**完整、合法的支持**，不是原 JSON 是否流畅或新名词数量。
同一表面动作在不同 scheduler 历史下可有不同结果；字符串不同也可能取得相同检索结果。

先做实际 rollout：

- 冻结索引、检索配置、reader、缓存策略和预算；
- 保存 raw/normalized/merged hypothesis、完整 pending、实际 issued、返回结果、可见 prompt；
- 对原 merge、新词优先、无 merge、去污染 hypothesis 做相同调用预算的比较；
- 同时比较普通 rewrite 训练；另报检索模型调用数和 token 数；
- 奖励支持修复而非 novel-doc 数；查询中的新实体必须可追溯到已见信息，不能偷看 gold。

如果收益全来自把旧词排序挪后，那是值得做的工程修复，但不构成独立训练创新。
如果只是多发查询或增加上下文，必须在预算匹配后重新比较。
本轮没有实际检索，故此方向暂不晋升主线。

### 6.2 互补证明集选择

把两段联合有效、单段不足的支持作为候选 bundle，比较同一候选池与最终 token 预算下的选择。
必要时先做候选池小规模穷举，确认原 top-k 确实遗漏了可放入预算的完整支持。

强对照包括原 chain rerank、top-k、MMR、条件动态选择和相同计算预算的宽搜索。
二阶交互公式本身不是创新；学到的选择策略必须胜过简单搜索。
如果 oracle 候选池里也没有支持，不能把召回缺口算成选择器错误。

## 7. 下一阶段 pilot：先证伪，再扩大

详细运行和验收规范见 [PILOT_PROTOCOL.md](PILOT_PROTOCOL.md)。

第一步不是直接用当前 84 条探针微调，而是新增约 30–50 个独立问题族做机制 pilot：
选择未参与 strict9 调参的故事/事件，优先覆盖嵌套转述、否定范围、主体方向、时间限定；
保留无此复杂性的事实控制。这个规模只用于发现问题，不承诺能检出小幅提升。

先冻结题设与必要答案，再审阅替代支持。按故事/事件/原文重叠组件划分，之后才派生变体；
同一故事的改名模板、近重复段、同题改述不得跨分区。
再引入独立公开领域作外推检验，其许可和版本要另行核验，不声称本轮已准备。

晋级要求：

1. 新自然样本上错误可重复，不仅是六个合成模板；
2. 同数据 SFT 后仍有可复现、与配对目标对应的残余错误；
3. 改善完整正确回答和引用支持，而不是靠全部弃答降低风险；
4. 对故事族和未见作用域组合有迁移，不靠姓名、长度、模板或历史答案；
5. 同预算强基线下仍有收益，并保留原可答题的退化计数。

停止或改题条件：

- 新颖性查全显示最近邻已经实质覆盖拟议机制；
- 普通 SFT/相同 schema 提示达到相同效果；
- 作用域图预测错误抵消收益，只有 oracle 图有效；
- 受控合成表现很好，自然盲测不改善；
- 标签不确定率高到无法稳定定义干预关系；
- 所谓恢复仍只来自静态补证，真实查询无法找到必要证据。

不以当前 9 个反复开发的问题族计算泛化显著性；按独立问题族做配对统计与置信区间。
正式样本量应依据 pilot 的模型间不一致比例、最小关注效应和预算确定，不把变体数当独立样本量。

资源上可沿原计划先试 4B LoRA、小批量和梯度累积，但 A100 的实际显存/并发状态、模型资产和训练时长均需运行前核验。
本轮未连接或占用两台远端，不承诺可并发启动，也不改变现有服务。
