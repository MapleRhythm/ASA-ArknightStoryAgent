# ASA 正确率提升研究：区分证据可见性与 reader 能力

日期：2026-09-08。承接 `SYSTEM_ACCURACY_DIAGNOSIS_20260908.md`。

同日后续已完成36条GPU生成及逐题复核，见
`QUOTE_RENDER_ABLATION_FINDINGS_20260908.md`。直接正文候选没有转化为
稳定最终正确率提升，不推广。下面保留生成实验前的离线研究与计划；
其中“尚未运行”的状态现已由后续报告更新。

## 结论先行

本轮没有新的生成结果或生产正确率。新增的是可复现的离线排除实验：

1. **不能把旧 gold ID 召回缺口当成这 9 题的主要失败原因。**当前 E-ID
   路径最终提示完整包含复核最小集的 13/13 段正文，覆盖全部 9 题。
   既有充分证据 reader 实验仍大量出错，优先处理归因、否定、完整性及动作。
2. **取消去重或简单改为按单段正文去重不是可用修复。**保持同样分数与
   top-k 后，完整最小集覆盖反而从 9/9 降到 6/9；不推广。
3. **quote 存在另一个具体问题：先拼长链，再截前 1000 字符，可能截掉
   被选中段落本身。**值得继续的候选是“选择器不变，只调整正文展示”，
   而不是再改检索。离线直接正文变体让完整最小集覆盖从 5/9 到 8/9，
   平均证据长度从 5673.33 降到 3942 字符。尚未证明答案更正确。
4. 全文缺失也不是语义不足。例如迷迭香题的正文尾部被截，但态度对比的
   必要句仍在；不能把这个失败代理指标当成回答评分。

本轮没有更改 `src/`、生产配置、checkpoint 或训练集；先前的安全修复和
其他未提交内容保留。早先那项未通过验证的生产去重试改已经撤回。
没有提交、推送或调用付费生成接口。

`production` 仅表示重放当前源码的默认选择算法，不证明线上进程正在用
这些配置或相同 snapshot。两个 baseline 的 selected IDs 均与冻结
snapshot 的 prompt IDs **9/9 完全一致**。

共 17 个离线条件 × 9 题 = 153 份渲染结果，没有153个新问题或模型回答。
检查旧24个 gold ID，同时检查复核最小集13个 ID、其支持组替代证据。
支持组的全文可见仍只是保守代理，不是原子要点的语义蕴含判决。

## 结果：哪些“修复”应该停止

| 路径 / 变体 | 完整最小集可见题数 | 可见最小集全文 | 平均证据字符 |
| --- | ---: | ---: | ---: |
| E-ID / 当前选择+渲染 | 9/9 | 13/13 | 4011.33 |
| E-ID / 选择前按单段正文相似去重 | 6/9 | 9/13 | 4344.89 |
| E-ID / 仅同 ID 去重 | 6/9 | 9/13 | 4377.00 |
| E-ID / 只删除全文被已有段包含的候选 | 6/9 | 9/13 | 4377.00 |
| quote / 当前选择+渲染 | 5/9 | 9/13 | 5673.33 |
| quote / 仅同 ID 去重 | 4/9 | 6/13 | 8452.00 |
| quote / 全文包含去重 | 5/9 | 9/13 | 5737.89 |
| quote / 选择不变，只展示直接正文 | 8/9 | 12/13 | 3942.00 |

同段相似去重变体仍用原0.82阈值；“全文包含”只检查空白归一化后的逐字
包含，不用99%词元重合。它们都只是本脚本内的候选，不 monkeypatch runtime。

改变去重会让更多高分相邻/同链段占满 top-k，并非免费恢复信息。
E-ID 的单段去重变体丢掉的复核最小集来自雷吉斯、莫斯提马和老天师三题。
这证明“表示不一致”值得诊断，但**不能凭源码直觉决定该改哪一层**。
特别是链分数与单段分数仍未重新校准，不能把这次结果泛化为所有直接正文
选择器必然更差。

对两个当前 baseline，预算提前 break 都是 **0/9**。把 break 改为
“跳过超长段继续找后续短段”，这批题没有任何变化。不以这个边界问题为由
修改生产 packing。仅同 ID 去重的 E-ID 变体有一题触发 break，但后面也
没有可装入的短段，skip 同样没有改善。

## 纠正“chain-visible”指标的含义

原 `evaluate_prompt_selection_ablation.py::visible_ids` 是外层 ID 加
`evidence_chain_member_ids` 的集合，未检查最终正文、截断或模式转换。
这是“链成员 metadata 覆盖”，不应叫“实际可见证据覆盖”。

| 当前路径，仍按旧24个 gold ID | 外层 ID 全覆盖 | 链成员 metadata 全覆盖 | 最终正文全文全覆盖 |
| --- | ---: | ---: | ---: |
| E-ID | 5/9 | 7/9 | 5/9 |
| quote | 5/9 | 7/9 | 3/9 |

但改用先前已复核的最小集，E-ID 的最终全文覆盖是9/9，而不是5/9。
旧 gold 里存在冗余替代段，莫斯提马的身份段也已被重新校正。因此旧表
“漏了4题”不能解读为当前 prompt 有4题证据不足，更不能作为增加检索轮数
或 top-k 的依据。旧报告不覆盖删除，本报告给出口径和局限。

## 下一步提升方案与停止条件

### P0：quote 展示 A/B，先回答“小改动是否真救题”

下一项最小生成实验是上述两种 quote 提示：同一冻结9题 ×2展示 =18输出。
固定实际部署的 quote reader、权重 SHA、解码参数、轮次、选段、E-ID顺序、
1000/12000预算；只改变链正文/直接正文。不能把 Exx 专训 adapter 临时
换上去又把差异归因于 renderer。上线配置和模型身份需要另行确认。

逐题同时审：

- 必要要点完整、没有未经支持的主体/否定/因果断言；
- 引文是否确实来自该 E-ID 的最终可见正文；
- 该答却检索/弃答、该检索却强答，以及生成截断；
- 输入/输出 token、真实端到端时延和内存，不用字符数代替 token。

开发 smoke 的进入下一阶段条件：恢复直接证据的题出现实际改善，且没有
已正确题因失去链上下文而退化。如果只有全文覆盖上涨、模型仍错绑人物，
不继续围绕这个 renderer 调参。即使18条都改善，也只能晋级独立问题族
确认，不能直接切生产。

### P1：reader 主体/否定/多子问训练，对照拆开做

既有108输出已说明通用提示不是稳定修复。下一版训练重点应是“从可见原文
学到关系和完整答案”，不是要求更积极 answer_directly。

先完成176个 after-scope候选的 fresh set audit，修订/新增项重新审核；
不要沿用174条冻结文件的局部审核。当前仅10条审核后 SFT，且全是
answer-only，不能据此代表完整训练配方或启动正式重训。

在通过分区门禁的新故事/事件数据上，为同一题建立四个可审核条件：

1. Full：所有必要信息可见，目标完整回答；
2. Distractor：必要信息不变，增加真实同场景干扰，正确事实保持不变；
3. Missing / 非末轮：删除关键支持及其替代证据，目标针对可识别缺口检索；
4. 同一 Missing / 末轮：目标弃答，而不是无依据补全。

Missing 不能只删一个 E-ID 就贴不足标签，必须检查其他块和原文重叠；
不能把标准答案或缺失正文直接放进生成器的 `missing_slots`。
角色归因、关系方向、否定、观点与事实、无依据因果的最小错例另用于
verifier/rejected目标，不混进正例答案。

使用实际服务协议训练：quote targets 绑定逐字可见引文，E-ID targets
仍用其原有 schema，不引入运行时没有的隐式思维字段。每个事实有效之后，
还必须判整题是否完整；裁判分歧继续隔离，不能通过多数标签自动洗白。

训练对照建议固定 base、分区、总训练 token 和步数：

- A：仅清洁后的 Full 正例；
- B：A + 归因/关系类型平衡及真实干扰；
- C：B + 经审核的 Missing/动作条件。

同题各条件在同一个 family；训练、开发、测试按事件/语义改写族共同隔离。
A/B/C 用相同训练 token预算，防止把多训练了数据误归因为方案本身。
本轮不指定这些尚未审核数据的最终数量或正负比例。

### P2：语义 verifier 和二次检索，先做影子评估

词法 grounding 能发现引文越界，不能阻止“没有同意→同意”。保持现有
结构校验，在隔离数据上评估语义 verifier 是否真正识别主体、模态与因果。
先只记录，不立即硬拒绝；必须同时报告错误放行和正确回答被误杀。
单个 GLM judge 的高通过率不构成生产 gate 的证据。

检索缺口必须来自问题和当前可见正文；隐藏 gold 仅用于事后奖励。
`build_gap_followup_sft.py` 当前直接消费上游 `known_covered` /
`missing_segment`，用正 coverage_gain 选样、按 source_name 分区；
本地尚未找到该上游数据来验证其来源。因此这里只确认**缺少输入来源
门禁的风险**，不声称已经证明该数据发生 oracle 泄漏。正式重训前需绑定
可见正文 SHA、缺口生成来源和 family，验证跟进检索有新支持信息且最终
答案更正确；仅 novelty 或 ID recall 增加不算成功。

### 统一验收门槛

strict9 只用于定位与 smoke，不再用来调提示后自称盲测。可预先规划至少
60个未用于开发/新训练的独立事件/问题族，覆盖主体、否定、因果、多子问、
证据不足；先确认历史 checkpoint 的监督曝光边界，不能“追溯性洗成”
held-out。每族四条件，baseline/candidate配对，约480输出；这只是预算
规划，未运行，样本量也不保证有足够统计功效。

主指标采用完整受支持回答率，按独立 family 聚合，并单列无依据回答率、
错误弃答和成本。提前冻结判据与裁判协议；对 complete、分歧及抽样失败
做独立复核，尽可能包括人类。报告配对置信区间；区间仍跨零就只能写
“证据不足以确认改善”，不靠 repeated conditions 扩大样本数。
候选需有可信的主指标净收益，且无依据回答、正确回答误杀及成本不超
预先约定的边界，才考虑部署。

## 本轮交付与边界

新增14项离线回归测试，覆盖：链元数据不等于正文、quote截断、预算break/
skip、首段超预算、同文不同ID、替代支持组、否定非重复、gold不参与选择、
