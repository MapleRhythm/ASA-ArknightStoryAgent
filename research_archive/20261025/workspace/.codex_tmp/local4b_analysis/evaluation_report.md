# 本地 Qwen3.5-4B+LoRA：8 题无代词改写复测

## 摘要

- 模型：`qwen3.5-4b` + `teacher_scored_kto_mix_v1_from_soda_lora_qwen35_4b_lr8e7_beta001_epoch2`。
- 题目：与 `v2_novel8` DeepSeek 对照完全相同的 8 题。
- 查询：8/8 的 `hypothesis.question` 与原问题逐字一致；每轮检索均保留原问题，没有把“它/她”替换为首实体。
- 协议：每轮最多 4 个检索查询，结论 prompt 选择 12 条完整 chunk；不做单文档或总字符截断。
- 质量：4 题正确，1 题基本正确，2 题错误弃答，1 题正确但表述过泛。严格全对率 4/8；宽松可用率 6/8；幻觉 0/8；弃答 2/8。
- 延迟：平均 52.616s，中位 45.247s；首题冷启动 73.451s；去掉首题后平均 49.639s。0/8 低于 20s。

## 运行前修复

本地入口此前没有消费 runtime 中的两个字段：

- `retrieval.max_retrieval_queries=4`
- `inference.prompt_evidence_require_full_documents=true`

这使第一轮试跑每轮展开 15--16 个查询，并让运行元数据错误显示为非全文模式。已修复本地入口、加入回归测试并提交：

```text
674694d inference: align local retrieval runtime options
```

相关测试：28 passed。修复后每轮实际查询数均为 4，运行元数据确认 `require_full_documents=true`。

## 逐题结果

### 1. 正确

- 回答：格拉尼认为钥匙吸血量有限，不愿让可萝尔承担致命风险；余下宝藏使大鲍勃一行在哥伦比亚安居、自给自足并计划试种啤酒花。
- 延迟：73.451s（含本地模型冷启动）；1 轮。
- 评审：两部分均正确。关键“大鲍勃信件”原始候选排第 16，但复合子主张 pinning 将其加入 12 条 prompt；这说明最终回答不能只按固定 top-12 截取。

### 2. 正确

- 回答：斯卡蒂交换的是幽灵鲨身上源石神经剂的来源；条件是必须听从凯尔希命令。
- 延迟：31.295s；1 轮。
- 评审：两项均被同一直接剧情 chunk 支持。

### 3. 基本正确

- 回答：第三下会下意识用尽全力、第四下挥不出来；凛冬和真理一起睡、擦眼泪并让她干活。
- 延迟：41.365s；1 轮。
- 评审：后两问正确；漏掉“坚雷最初以为只是克服一个关卡/习惯问题”这一子问，因此只算基本正确。相比 DeepSeek 的“凛冬擦眼泪、真理递手帕”，本地回答没有虚构动作归属，但措辞不够准确（原文是凛冬用真理的手帕擦眼泪）。

### 4. 错误弃答

- 回答：输出三段无关/弱相关证据后表示缺少完整证据。
- 延迟：60.090s；2 轮。
- 评审：检索池里买店动机排第 5，但“父亲是理发师”的 chunk 排第 23，“苦根就是房东”的 chunk 排第 24。复合子主张 pinning 没把后两条选入 prompt，随后第二轮仍未形成有效 query，最终又因 quote_not_found 进入 fallback。这里主要是 prompt 证据覆盖与 quote 协议问题，不是“4B 看见正确证据仍不会回答”。

### 5. 正确但过泛

- 回答：雷德用自己嘴角有血、对方手破制造感染恐惧；实际只是擦破皮，风险很低；示威者身份和说辞反复变化，因此疑似受雇。
- 延迟：93.072s；2 轮。
- 评审：核心事实正确，但“反常经历”没有明确列出一个月前冒充工厂工人、两个月前冒充商贩、当日又自称搬运工。首轮证据已齐，却因 quote_not_found 把格式错误误判成缺证并多跑一轮，延迟被放大。

### 6. 错误弃答

- 回答：现有证据不足以确认。
- 延迟：45.833s；2 轮。
- 评审：关键剧情是 `act10d5_st06#chunk-0014`，但在最终 32 条证据池中完全缺失；系统召回的是大量 `st04` 片段。这里是候选召回失败。4B 将“后勤/前线/批准”等表面词做成实体，并在第二轮继续查询单词“阿米娅/娜塔莉娅/前线”，没有产生“无助/强制保护/尊重选择”等真正补证词。DeepSeek 能在同配置下把该长 chunk 排到第 14 并通过子主张选择钉入 prompt，说明 hypothesis/query planning 模型能力差异是关键因素之一。

### 7. 正确

- 回答：霜星过去怕全力伤到雪怪小队；交战时成员均已死亡、身边没有活物，所以不再压制力量。
- 延迟：31.158s；1 轮。
- 评审：直接证据充分，回答准确。

### 8. 正确克制

- 回答：现有证据不足以确认。
- 延迟：44.661s；2 轮。
- 评审：没有虚构人名或日期，语义上正确；但表述不如 DeepSeek 完整。正确证据（凯尔希只说“来源”，未给具体人名和日期）已在第 10 条 prompt 内，4B 仍先请求补检索，说明它对“证据未写明”的否定性回答策略训练不足。

DeepSeek：严格 4/8，宽松 5/8，幻觉 1/8，系统错误弃答 1/8，平均 11.904s。

本地 4B：严格 4/8，宽松 6/8，幻觉 0/8，错误弃答 2/8，平均 52.616s。

结论是：4B 不是整体不可用，直接证据进入 prompt 时可稳定答对；但它更容易漏子问、把可回答问题判断成需补证，并生成低质量 follow-up query。当前 LoRA 的核心短板不是基础事实复述，而是规划动作、完整子主张覆盖和否定性证据判断。

## 主要链路痛点

1. `hypothesis + conclusion` 两次本地生成本身已超时。稳态单轮题平均 34.606s，其中 hypothesis 7.037s、检索 4.910s、conclusion 22.659s。即使检索降到 0，也很难达到 20s。
2. 两轮策略代价过大。稳态两轮题平均 60.914s；Q5 的 quote 格式错误把本可一轮完成的问题拖到 93.072s。
3. query cap 当前按列表顺序截断。4 个名额常被“原问题 + hypothesis 摘要 + 单实体词”占满；复合问题的后半子主张几乎得不到独立 query。Q1 幸亏 prompt pinning 补救，Q6 则彻底漏召回。
4. 复合子主张 pinning 不稳定。它能修复 Q1，却没修复 Q4；特别是身份题和因果题的局部启发式要求过严，容易把第 23/24 条关键证据留在 prompt 外。
5. quote_not_found 仍被当作 `retrieve_more`。证据已齐时应只做短格式修复，不应重新检索。
6. 负事实回答策略不足。Q8 已有足够边界证据，但 4B 仍多跑一轮后才给泛化弃答。

## 建议优先级

1. 将推理规划从“hypothesis 生成 + conclusion 生成”压缩为一次答案生成；检索 query 采用原问题加确定性子问题分解，取消本地模型 hypothesis 调用。按本轮耗时估算，可先省约 7s。
2. query cap 改为按槽位分配：原问题 1 条、每个子主张 1 条、剩余名额给实体/关键词；禁止单个实体词抢占复合子问名额。
3. 修复 quote retry 路由：`quote_not_found` 只把失败 claim 和目标 evidence_id 回传做一次短连续 quote 重写，不触发重新检索。
4. 将回答生成改成短 schema（answer + evidence_ids），连续 quote 由程序从 evidence_id 对应 chunk 中抽取/校验；这可减少 4B 输出 token 和格式错误。
5. 为本地 SFT/KTO 补三类 hard case：多子问必须逐项回答；证据未明示时做“未写明”回答；证据已齐时禁止 `retrieve_more`。Q3/Q8/Q5 可直接作为模板，但训练集应换不同剧情避免泄漏测试题。
6. 召回侧优先增加“子问题独立召回 + story/chapter 聚合”，而不是继续扩大统一 top-k。Q4/Q6 的失败都说明真正需求是覆盖不同子主张/章节。
