# 针对错因扩数据并重训 P-tuning v2

## 范围

- 新增目标为 600 条新中文问题：从 200 个不同的旧训练证据包中，每包生成 3 题。
- 证据包来自已审计的 v1 **训练**数据，不读取旧答案设计新题；这是扩充问题覆盖，不是扩充故事语料。
- 每题保留 20 段全文、原生 E-ID 协议，无输入截断。
- 类型为人物/说话者归属、时间与场景范围、两个子问/比较、缺证处理。
- 每包含两个可回答问题和一个设计为缺证的问题。实际动作由重新标注和语义复审决定，不把题目设计者的意图当成金标。
- 1/2、2/2 均衡设置，分别训练可补检索与最终轮缺证边界。

## 留出保护

- 原 46 行验证数据逐字节保留，不写入训练，不将内容复核答案提供给教师。
- 保护所有 v1 验证来源 family：act15d0、act17d0、act18d0、act18mini、act19mini、act2vmulti、multiv3、obt/main。
- 继续保护 act10d5、act10mini。
- 对 family、正文 document ID、规范化问题分别检查训练/验证不相交。
- 新问题还须不同于全部旧训练/验证问题。
- 这 46 题已用于开发和错因分析，因此不能宣称是盲测或未见 benchmark。

## 标注与审计

- 仅使用 `https://open.bigmodel.cn/api/coding/paas/v4/chat/completions`，模型 `glm-5.3`，不回退普通计费端点。
- 题目生成不请求答案。生成题再次提交完整证据，取得全新标签。教师另有版本化离线质量指令（必要的 1–3 条事实），学生原生 prompt 不变；实际教师请求由原生消息与教师附加指令重建，核对 API cache key。
- 每个新标签均以另一请求做语义复审，核对人物归属、事实支持、子问覆盖、无据增写及动作轮次。
- 复审与标注使用同一 GLM：不是独立人工金标，不宣称全部标签语义已被证明正确。
- 不修补标签；失败、语义复审不通过，或复审虽然给了通过标志但 issues 非空的样本都隔离。
- SQLite 缓存、预算调用前预留、有限重试、熔断和断点恢复；保存 API 回执与哈希。
- 正式批次两阶段合计最多 2,080 次请求尝试、2,000 万 accounted tokens；它是保守预算上界，不是消费或账单估计。
- 小批量预检额外独立计数。首轮预检暴露出“核心正确但复审放过引用缺口/重复”的问题，故收紧教师指令并采用上述保守离线筛选；首轮产物与脚本保留，不用改后的脚本解释旧结果。
- 正式批次须全部处理完，至少保留 350 条新样本、四类型各 50 条，方可合并和训练。
- 旧审计器继续审核每个独立来源，新审计器核对合并结果及每个新标签的第二轮复审回执。

## 新版训练

- 审核通过的新训练数据混入旧 280 条；原 46 行验证不变。
- 单独目录和版本，保留 v1 和全部旧产物，不修改生产发布。
- 冻结 Bonsai 2 27B 主干，只训练 16 个 soft tokens 和外置两层 residual MLP（2,708,736 参数）。
- 与 v1 一致的初始化、1 epoch、学习率 2e-5；这是重新训练，不是偷换数据后恢复旧 optimizer。
- CPU activation offload；新合并集最长全文输入须真实通过前向/反向、梯度、显存 gate。
- 训练时再验数据、gate、后端和训练代码；保存逐步 optimizer checkpoint。
- 训练前检查 GPU 1 的空闲显存，不停止别人的作业。
- 无在线规则校验、输出修复；原生 GGUF soft-token 注入部署仍未验证。
- 训练结束只代表训练完成。仍须在固定 46 题上生成并复核，不能用 NLL 冒充回答正确率。
